# 資料庫引擎（KV / SQL / 索引 / 佇列）

資料庫引擎是把「資料結構」組裝起來，對外提供 **Key-Value（KV）儲存、SQL 查詢、全文檢索、甚至訊息佇列**能力的完整系統。理解資料庫本質上就是理解底下那幾棵樹與幾張索引如何分工。

## 資料庫的三層骨架

一個精簡的資料庫引擎通常分三層：

1. **儲存引擎（storage engine）**：負責把資料放在記憶體或磁碟上，提供「寫入一個鍵、讀出一個鍵」的基本能力。
2. **執行器（executor）**：把 SQL 等查詢語言轉成對儲存引擎的實際呼叫。
3. **介面層**：對外提供 SQL、KV API、FTS 或佇列等使用介面。

## 儲存引擎：可替換的資料結構

儲存引擎可以掛上不同的資料結構來適應不同情境：

| 引擎 | 底下結構 | 特性 | 適用 |
|------|----------|------|------|
| Memory | 記憶體中的有序映射 | 快、無持久性 | 原型、快取 |
| BTree | 磁碟 [B-Tree](B樹.md) | 就地更新、支援範圍掃描、可持久化 | 一般用途 |
| LSM | [LSM 樹](LSM樹.md) | 寫入快、靠合併維護有序 | 寫入密集 |

不同引擎背後的介面一致，因此「換引擎」不改動上層邏輯——這就是「可插拔（pluggable）儲存引擎」的設計。

## SQL：解析 → 規劃 → 執行

SQL 只是「告訴系統要什麼」的宣告式語言。引擎內部要做：

1. **解析（parse）**：把 SQL 文字變成語法樹。
2. **規劃（plan）**：把語法樹轉成執行計畫，例如決定要用哪個索引、以何種順序 JOIN。
3. **執行（execute）**：依計畫實際呼叫儲存引擎取得資料。

「用哪個索引」正是資料庫效能的分水嶺——查「鍵」用 [SwissTable](swiss表.md) 或 B 樹索引，查「前綴/範圍」用 [Patricia Trie](Patricia樹.md) 或 B 樹。

## Full-Text Search（FTS）：SQL 裡的反向索引

「資料庫能不能做 LIKE 全文搜尋」速度很慢，因為那要全表掃描。現代引擎會在 SQL 之上疊一套全文檢索：把要搜尋的文字建成[反向索引](反向索引.md)，把查詢關鍵字翻譯成對反向索引的擷取，再用 BM25 排序。如此中文/英文的關鍵字檢索都能在大量資料上快速地回傳命中與相關度排序。

## 訊息佇列（Message Queue / Msgq）

同一個引擎也能再疊一層**佇列**能力：把「追加一筆資料」映射到底下 KV/有序結構的 append 操作，讓多個消費者能依序取出並各自推進指標。這讓「資料庫」與「事件佇列」共用同一份儲存核心，減少系統數量。

## 關鍵取捨

- **持久性**：write-ahead log（WAL）保保證雖然記憶體引擎很快，但真正要耐久就得先寫日誌。
- **一致性**：B 樹可支援完整交易；LSM 靠合併與層級控制。
- **寫 vs 讀**：寫密集選 LSM，讀/範圍查詢選 B 樹。
