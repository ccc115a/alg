# SwissTable（Swiss Table）

Swiss Table 是 Google 開發、並用於其標準函式庫的高效能**雜湊表**實作技術。它把「開放定址」與寫在一個小小的 metadata 陣列上、可一次檢查一整組槽位的技巧結合起來，達到極佳的快取與偵測效能。

## 核心問題：雜湊表要怎麼快

傳統的鏈結雜湊表（separate chaining）把衝突的鍵放在一個鏈結串列裡。這有兩個問題：

1. **快取不友善**——每個節點散落在記憶體各處，讀一個鍵往往觸發多次快取失誤。
2. **名稱無關的浪費**——每個鍵要額外存一個指標去指到節點。

Swiss Table 改用**開放定址**：所有元素住在同一塊連續陣列裡，彼此緊鄰，快取命中率高得多。

## Metadata 陣列與「控制位元組」

Swiss Table 的關鍵發明是：除了存放鍵值的陣列，還並排維護一個 **metadata 陣列**，每個槽位對應一個 metadata 位元組，用來記錄這個槽位目前的狀態：

- 空（empty）
- 已使用（occupied）
- 被刪除／墓碑（tombstone）

在**空白與存量充足**時，更重要的細節是：這個位元組會存下該鍵雜湊值的一部分（例如末 7 個位元）。於是「找鍵」時，**不用先碰真正的鍵值**，只要先比對 metadata 就能快速跳過絕大多數不相干的槽位。

## 群組（group）與 SIMD 偵測

槽位被切成固定大小的**群組**（例如一次 16 個槽位，剛好對齊一個 SSE/AVX 暫存器）。搜尋時：

1. 算出鍵的雜湊值。
2. 從對應的群組出發，一次把**整個群組**的 metadata 載入 SIMD 暫存器。
3. 用一條「比較等於」的指令同時比對 16 個位元組，找出哪幾個槽位的 metadata 與目標位元組相同。
4. 只對這些少數「疑似命中」的槽位，才去真正比較鍵值。

因為最有望命中的槽位都在同一個快取行裡，加上 SIMD 能一趟檢查一整組，Swiss Table 的**快取與分支預測**都遠優於傳統做法。偵測失敗（沒命中）時，脈絡核心使用近似羅賓漢（Robin Hood）的規則抉擇插入位置，以控制偵測距離的變異、維持高載入因數（通常可用到 87% 以上）。

## 為什麼它既快又省

- **記憶體連續**：所有資料在單一陣列裡，減少 cache miss。
- **SIMD 群組偵測**：一次比對一整組，減少分支與次要記憶體存取。
- **高載入因數**：同樣容量下用更少的記憶體。
- **中繼資料小**：每個槽位只付出 1 個 control byte 的代價。

## 相關結構

- 與 [B-Tree](B樹.md)（有序、磁碟導向）不同，Swiss Table 是**記憶體導向、無序**的雜湊表，適合快速精確查找。
- 想在集合內快速前綴/範圍查詢時，則改用 [Patricia Trie](Patricia樹.md) 等有序結構。
