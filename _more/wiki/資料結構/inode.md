# Inode

Inode（**index node**）是檔案系統中描述**單一檔案或目錄**的資料結構。它不存放檔案內容本身，而是存放關於這個檔案的「身份與索引」資訊，並指向實際存放資料的區塊。

## 為什麼需要 inode

傳統的檔案系統把「檔名」和「檔案本體」分開管理。目錄只是一個「檔名 → inode 編號」的對照表；真正描述檔案的資訊（擁有者、大小、存放在哪個磁碟區塊）全部集中在 inode 裡。這樣做的好處：

- **多個檔名可指向同一個檔案**（hard link / 硬連結）——因為它們都指向同一個 inode。
- **檔名不再綁死內容**——改名、移動只需要改目錄項，不必動到資料。
- **中繼資料集中管理**——權限、時間戳、連結數一目了然。

## Inode 裡面放什麼

典型的 inode 包含：

| 欄位 | 作用 |
|------|------|
| 檔案類型 | 一般檔、目錄、符號連結、設備檔… |
| 權限與擁有者 | mode、UID、GID |
| 時間戳記 | 建立、修改、存取時間（ctime / mtime / atime） |
| 大小 | 檔案長度（bytes） |
| 連結計數 | 有多少個目錄項指向它 |
| 資料區塊指標 | 指向實際資料所在的位置 |

## 資料區塊的指標策略

檔案可能很大，但 inode 必須保持固定大小。因此資料區塊指標混合了「直接」與「間接」兩層：

- **直接區塊**：幾個固定數目的指標直接指到資料區塊，適合小檔案。
- **單層間接、雙層間接、三層間接**：層層指過去，讓 inode 用很少的空間就能定址極大的檔案——這就是為什麼小檔案能非常省空間，而大檔案依然可以在檔案系統支援的範圍內成長。

這種「固定大小 inode + 分級間接」正是 Unix 檔案系統的經典設計。

## 與目錄的關係

目錄本身也是一個檔案，內容是一連串的「檔名 + inode 編號」目錄項。尋找檔案的路徑（例如 `/home/user/doc`)其實是**逐層查詢目錄項**：根目錄的 inode 是固定的（root inode），從根往下，每進一層就依目錄項找到下一層的 inode，直到最後一個檔案的 inode。
