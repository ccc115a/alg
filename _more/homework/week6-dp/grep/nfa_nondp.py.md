# nfa_nondp.py — Thompson NFA 模擬 regex 引擎

## 用途

以「編譯成 NFA + 並行模擬」實作 regex 比對，支援
字元、`.`、`*`、`|`、`()`——這是 grep/egrep 的核心原理。

## 類別與函式

| 名稱 | 說明 |
|---|---|
| `NFA(pattern)` | 編譯 pattern 成 NFA（Thompson 構造） |
| `NFA.match(text)` | text 是否完全匹配 pattern（fullmatch） |
| `nfa_match(s, p)` | 便捷函式 |

## 原理：Thompson 構造

| 語法 | NFA 結構 |
|---|---|
| 字元 `c` | 一條 `c` 轉移邊 |
| `.` | 一條「任意字元」轉移邊 |
| 串接 `AB` | A 的出口 ε 到 B 的入口 |
| `\|` | 入口 ε 到兩分支，兩分支出口 ε 到匯合點 |
| `*` | `cur --ε--> body --ε--> out`、`cur --ε--> out`（跳過）、`out --ε--> body`（環） |
| `(…)` | 遞迴解析子表達式；group 也可加 `*` |

## 原理：並行模擬

維持「當前可能處於的狀態集合」：

1. 初始 = `{start}` 的 ε-closure
2. 讀入字元 `ch`：收集所有 `--c-->` 且 `c == ch 或 c == '.'` 的目標
3. 對結果再做 ε-closure
4. 接受狀態 ∈ 集合 → 目前前綴匹配成功

## 狀態機結構（`(a|b)*` 範例）

```
0 --ε--> 7 (body) --ε--> 2 --a--> 4 --ε--> 3 --ε--> 8 (out)
0 --ε--> 8                2 --ε--> 5 --b--> 6 --ε--> 3
8 --ε--> 7 (重複)         8 --ε--> 1 (accept)
```

## 複雜度

- 編譯 **O(|p|)**（每個符號建 O(1) 個狀態）
- 模擬每字元 **O(|p|)**（ε-closure 均攤），總計 **O(n·|p|)**
- 空間 **O(|p|)**（狀態集合 + 轉移表）

## 與 DP 的關係

`dp[i][j]` 恰好等於「讀完 s 前 i 字元後，NFA 處於狀態 j」——
DP 表就是模擬過程的表格化。NFA 視角的優勢在於擴充文法容易
（加 ε 邊即可），且更貼近工業引擎（grep 用 Thompson NFA，
RE2 用 NFA→DFA）。

## 已知限制

- 不支援 `+`、`?`、字元區間 `[a-z]`（可輕易用 ε 邊擴充）
- 每次 `nfa_match` 都重新編譯；實務引擎會 cache 編譯結果
