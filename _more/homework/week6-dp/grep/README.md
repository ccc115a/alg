# 3. grep — 正規表達式比對

## 問題

實作一個正規表達式引擎的匹配核心：支援字元、`.`（任意字元）、
`*`（前驅零次或多次）、`|`（分支）、`()`（分組）的子集。

## 解法一：動態規劃（`dp_match.py`）

### 原理

經典的 `dp[i][j]`：`s` 前 `i` 字元是否完全匹配 `p` 前 `j` pattern。
處理 `*` 時分「零次」與「一次以上」兩支轉移。

### 狀態與轉移

- `dp[i][j]`，`0<=i<=n`、`0<=j<=m`
- 普通 token / `.`：`dp[i][j] = dp[i-1][j-1] and token 匹配 s[i-1]`
- `*`（前驅 token `p[j-2]`）：
  - 零次：`dp[i][j] = dp[i][j-2]`
  - ≥1 次：`dp[i][j] = dp[i-1][j] and token 匹配 s[i-1]`
- 初值：`dp[0][0]=True`；`dp[0][j] = dp[0][j-2]`（處理 `a*` 型）

### 複雜度

- 時間 **O(nm)**、空間 **O(nm)**（可壓 O(m)）

## 解法二：Thompson NFA 模擬（非 DP，`nfa_nondp.py`）

### 原理

grep/egrep 的歷史作法（Thompson 1968）：

1. **編譯**：把 pattern 構造成 NFA——每個字元一個狀態、`*` 加 ε-環、
   `|` 建分支、`()` 串接子機器
2. **模擬**：維持「當前可能處於的狀態集合」，每讀一字元做 ε-closure +
   轉移；集合含接受狀態即匹配

### 複雜度

- 編譯 O(|p|)，模擬每字元均攤 O(|p|)，總計 **O(n·|p|)**，空間 O(|p|)

## 比較

| | DP 表格 | NFA 模擬 |
|---|---|---|
| 本質 | `dp[i][j]` = NFA 在第 i 字元後處於狀態 j | 同一件事的「集合視角」 |
| 時間 | O(nm) | O(n·|p|) |
| 擴充性 | 加 `+`、`?`、字元區間需改轉移 | 加 ε-邊即可，結構優雅 |
| 實務 | 程式題常見（LeetCode #10） | **真實 grep/RE2 的基礎** |

**結論**：兩者在理論上等價（DP 表 = NFA 的逐字元推進），
但 NFA 視角更容易擴充文法、也更貼近工業界引擎（grep 用 Thompson NFA，
RE2 用 NFA→DFA）。DP 解法勝在實作簡單、易加記憶化。
