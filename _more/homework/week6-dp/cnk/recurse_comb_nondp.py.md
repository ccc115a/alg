# recurse_comb_nondp.py — 純遞迴求 C(n,k)

## 用途

以未記憶化的純遞迴計算 C(n, k)，示範「重疊子問題」造成的指數爆炸。

## 函式

| 函式 | 說明 |
|---|---|
| `comb_recursive(n, k)` | 直接展開 Pascal 公式的遞迴 |
| `comb_factorial(n, k)` | 階乘公式（利用 `math.factorial`，非遞迴樹） |

## 原理：直接展開定義

```
C(n, k) = C(n-1, k-1) + C(n-1, k)    # Pascal 公式
C(n, 0) = C(n, n) = 1
```

每次呼叫分裂成兩個子呼叫，形成二元遞迴樹。

## 為什麼慢：重疊子問題

以 C(5,2) 為例：

```
        C(5,2)
       /      \
    C(4,1)   C(4,2)      ← C(4,1) 被算兩次
    /   \    /   \
 C(3,0) C(3,1) ...      ← C(3,1) 等又重複多次
```

同一個 `C(i,j)` 出現在樹中多個位置，每次都要重新展開。
遞迴樹節點總數為 **O(2^n)** 級（即使 k = n/2 也一樣）。

## 階乘公式

```
C(n, k) = n! / (k! · (n-k)!)
```

時間 O(n)（求階乘），但：
- 大 n 時中間階乘巨大（Python big-int 尚可，C/C++ 會溢位）
- 需要取模時除法不可直接做（要用 modular inverse）

## 複雜度比較（實測）

| n, k | 純遞迴 | DP (1D) |
|---|---|---|
| 20, 10 | 12.8 ms | 4.5 µs |
| 25, 12 | 361 ms | 6.4 µs |
| 28, 14 | 2790 ms | 7.9 µs |

遞迴每 +2，時間 ×4~8；DP 幾乎線性成長。

## 結論

這是「需要動態規劃」的最小教科書範例：
- **重疊子問題**：相同 `(n,k)` 反覆計算
- **最優子結構**：答案由子答案組合而成
- 加 memo（top-down）或改 bottom-up 表格 = 動態規劃
