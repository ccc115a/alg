# 6. cnk — 排列組合 C(n,k)：遞迴 v.s. 動態規劃

## 問題

計算 C(n, k) = 從 n 個不同物品取出 k 個的組合數。

## 解法一：動態規劃（`dp_comb.py`）

### 原理

Pascal 公式：每個元素「取或不取」。

### 狀態與轉移

- `dp[i][j]` = C(i, j)
- `C(n, k) = C(n-1, k-1) + C(n-1, k)`（取第 n 個 / 不取第 n 個）
- 初值 `C(i, 0) = 1`、`C(i, i) = 1`
- 空間壓縮：一維 `dp[j] += dp[j-1]`，j 從大到小更新

### 複雜度

- 時間 **O(nk)**、空間 **O(k)**（壓縮後）或 O(nk)（2D 版）

## 解法二：純遞迴（非 DP，`recurse_comb_nondp.py`）

### 原理

直接展開 Pascal 公式，不做任何記憶化：

```
C(n,k) = C(n-1,k-1) + C(n-1,k)
```

每個子問題都重新展開，形成指數大的遞迴樹。

### 複雜度

- 時間 **O(2^n)**（遞迴樹節點數）、空間 O(n)（遞迴深度）

另附階乘公式 `C(n,k) = n!/(k!(n-k)!)`——用大數整數時需小心溢位。

## 比較

| | 純遞迴 | DP |
|---|---|---|
| 原理 | 直覺展開定義 | 記住每個子問題的答案 |
| 時間 | O(2^n) | O(nk) |
| 空間 | O(n) 遞迴深度 | O(k)（壓縮） |
| 重疊子問題 | 重複計算 C(n-1,k) 等，呈指數爆炸 | 每個 (i,j) 只算一次 |

**結論**：這是「重疊子問題 + 最優子結構 → 需要 DP」的最小範例。
n=28, k=14 時遞迴需數百萬次呼叫，DP 只需 28×14≈400 次加法，
差距隨 n 指數擴大。加了 memo 的遞迴（top-down DP）即為兩者的橋樑。
