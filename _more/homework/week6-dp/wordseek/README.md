# 4. wordseek — 單字搜尋的極致：Boyer-Moore v.s. 動態規劃

## 問題

在大字串/文本中搜尋目標單字。有兩個經典變體：

1. **精確匹配**：找到 pattern 完整出現的所有位置
2. **模糊定位**：容忍錯字，找「最像」目標的單字（拼寫檢查）

## 解法一：Edit Distance 動態規劃（模糊搜尋，`dp_search.py`）

### 原理

編輯距離 = 把 A 變成 B 所需的最少插入/刪除/取代次數。
對字典中每個候選計算與 query 的編輯距離，取最小者。

### 狀態與轉移

- `dp[i][j]` = `query` 前 `i` 字元 vs `candidate` 前 `j` 字元的編輯距離
- 相同 → `dp[i-1][j-1]`；不同 → `1 + min(刪, 插, 代)`
- 初值 `dp[i][0]=i`、`dp[0][j]=j`

### 複雜度

- 每候選 O(|q|·|c|)，全部候選 O(Σ|c|·|q|)
- 可用長度差剪枝（`abs(len差)>k` 直接跳過）

## 解法二：Boyer-Moore（精確搜尋，非 DP，`boyer_moore_nondp.py`）

### 原理

從 pattern **右端**往左比，失配時大幅跳躍：

1. **壞字元規則**：失配字元在 pattern 中最右位置 → 跳 `j - bad[x]`
2. **好後綴規則**：已匹配後綴在 pattern 別處的出現位置 → 跳對應距離
3. 取兩者較大跳量

### 複雜度

- 平均 **O(n/m)**（每個「窗口」比 m 個字元即可跳 m 以上）、最壞 O(nm)
- 預處理 O(m·σ + m)

## 比較

| | Edit Distance DP | Boyer-Moore |
|---|---|---|
| 任務 | 模糊匹配（容忍錯字） | 精確匹配（最快） |
| 時間 | O(nm) / 每候選 | 平均 O(n/m) |
| 輸出 | 最相似候選 + 距離 | 精確出現位置 |
| 應用 | 拼寫檢查、DNA 近似比對 | grep -F、文本編輯器尋找 |

**結論**：兩者其實解不同子問題——「要快找精確字」用 Boyer-Moore
（不需要 DP），「要找最像的字」則非 DP 不可用（必須比較所有可能性）。
若把 DP 用於精確匹配（如 `dp[i][j]` 檢查相等），反而 O(nm) 遠遜於 BM，
顯示 DP 的價值在「需要比較/取捨的問題」而非「結構性跳躍」。
