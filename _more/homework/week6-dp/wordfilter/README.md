# 5. wordfilter — 海量敏感詞過濾：Aho-Corasick v.s. 動態規劃

## 問題

在長文本中，同時檢查是否包含數千～數百萬個敏感詞，
並支援「精確命中」與「錯字/變體命中（編輯距離 ≤ k）」。

## 解法一：trie + DP 模糊匹配（`dp_filter.py`）

### 原理

把敏感詞建成 trie；從文字每個位置出發，在 trie 上用
「編輯距離 ≤ k」的 DP 往下走。走到詞尾且花費 ≤ k 即命中（模糊）。

### 狀態與轉移

- `cur[node] = 從起始位置 i 走到 trie node 的最小編輯距離`
- 轉移：完全匹配 → `cur[child] = min(現值, cost)`
- 取代 → `cost+1` 到 child（用不同字元）
- 插入 → `cost+1` 留在同一 node（跳過 trie 字元）
- 删除 → `cost+1`（跳過文字字元）
- 若 node 是詞尾且 `cost ≤ k` → 命中

### 複雜度

- 每起始位置 O(k · trie 節點數 × branching)；總計 O(L·k·T)
- k=0 時退化為精確 trie 掃描

## 解法二：Aho-Corasick（非 DP，`aho_corasick_nondp.py`）

### 原理（AC 自動機，1975）

1. 所有敏感詞建 trie
2. BFS 建 **fail link**：失配時跳到「最長仍匹配的真後綴」
3. **output link**：fail 指到詞尾也收集（處理子串命中，如「敏感詞典」含「敏感詞」）
4. 掃描文字：每字元 O(1) 走 trie、沿 fail 跳，收集 output

### 複雜度

- 建機 **O(Σ|word|)**，掃描 **O(全文長 + 命中數)**
- 與詞庫大小幾乎無關——百萬級詞庫也能單遍掃完

## 比較

| | trie + DP | Aho-Corasick |
|---|---|---|
| 匹配類型 | **模糊**（編輯距離 ≤ k） | **精確** |
| 時間 | O(L·k·T)，隨詞庫成長 | O(L + hits)，近常數於詞庫 |
| 詞庫規模 | 小～中（百級） | 百萬級（工業標準） |
| 應用 | 變體偵測、拼寫容錯 | grep、IDS/敏感詞過濾、入侵檢測 |

**結論**：AC 用 fail link 把「多模式搜尋」的複雜度壓到與詞庫無關，
但只會精確命中；trie+DP 能抓變體但代價隨詞庫爆炸。
**實務做法是兩層**：先用 AC 精確掃一遍（快），對高風險片段再用
DP 做模糊驗證（準），兼顧效率與韌性。
另一個有趣事實：AC 機的 fail 樹上「沿 fail 走」其實可視為
以 DP/自動機視角重新詮釋多模式匹配——圖論與 DP 在此交會。
