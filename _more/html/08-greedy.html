08 貪婪法 每一步都選「眼前最佳」，希望全域也最佳

貪婪法不做後悔能做的事：每一步只顧「現在看來最好的選擇」，然後繼續走下去。 有的問題（找零錢某些幣制、Huffman、最小生成樹）這樣就能得到全域最佳；有些則不能——所以貪婪法最重要的課題是判斷它會不會失敗。

08.1 找零錢：貪婪常常對，但偶爾會「輸」

先用最大的硬幣湊，能拿就拿。幣值 {1, 3, 4} 時湊 6：貪婪先拿 4，剩 2 → 只能拿 1、1，共 3 枚； 其實最佳是 3 + 3 只有 2 枚。這個反例說明貪婪「眼前最好」不一定等於「整體最好」。

貪婪找零 vs 最佳解黃 = 貪婪的一步一步；數字下方顯示最佳枚數

08.2 哈夫曼編碼 Huffman：把最常出現的字元編最短

把每個字元當成葉節點，權重 = 出現次數；每次合併最小的兩個，形成一棵二元樹。 樹上左邊寫 0、右邊寫 1，每個字元的編碼就是「從根走到它的 0/1 串」——出現越頻繁，路徑越短。

Huffman 樹建構動畫每一列 = 一次合併；結束後顯示完整編碼表

08.3 最小生成樹 Kruskal：每次都挑「最便宜且不形成環」的邊

要讓 n 個城市連通、且總成本最低，就是最小生成樹 (MST)。 Kruskal 的貪婪策略：每次看最便宜的邊，只要它在圖中不形成環就選（用併查集 union-find 檢查），直到選滿 n−1 條。

Kruskal MST 動畫綠 = 選取（併入），紅虛線 = 形成環被捨棄

什麼時候貪婪才正確？
貪婪要保證全域最佳，通常需要「貪婪選擇性質」（Greedy-choice property）+「最佳子結構」。 零錢（一般幣制）、背包（分數版）會出錯；Huffman、MST、活動選擇則被證明正確——判斷正確性正是貪婪法最重要的一課。
