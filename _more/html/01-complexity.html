01 複雜度分析 Big-O：演算法到底有多快？

同樣的輸入，不同的演算法可能快上 十億倍。複雜度分析讓我們不寫程式、不量秒數，也能預測一個演算法在輸入變大之後會變得多慢。

01.1 為什麼要分析複雜度？

判斷一個程式「快不快」，不能用秒數——因為同一個程式在不同機器上跑的快慢不同。所以我們改用操作次數來衡量：輸入大小為 n 時，演算法大約執行了多少次基本運算。

# 線性搜尋：檢查 n 個元素，最多 n 次
def linear_search(a, key):
    for x in a:            # ← 這個迴圈最多跑 n 次
        if x == key:
            return True
    return False

當 n 從 1000 變到 100 萬時，這個程式的操作次數也大約放大 1000 倍——這就透過 O(n) 這個記號來表達。

定義
Big-O（上界）：我們寫 f(n) = O(g(n))，若存在常數 c>0 與 n₀，使得對所有 n ≥ n₀，都有
0 ≤ f(n) ≤ c · g(n)。
Big-Ω（下界）：f(n) = Ω(g(n))，若存在 c>0、n₀，使 f(n) ≥ c·g(n) 對所有 n ≥ n₀ 成立。
Big-Θ（同階）：f(n) = Θ(g(n))，若同時 f(n) = O(g(n)) 且 f(n) = Ω(g(n))，表示兩者長得一樣快。
直覺：O 是「最多不超過」、Ω 是「至少也這麼多」、Θ 是「剛好這個量級」。 平時說「這個演算法是 O(n²)」，意思是操作次數頂多跟 n² 成正比。

01.2 體驗：成長曲線

不同複雜度在 n 小時看不出差別，但 n 一到 30～50，指數級曲線直接衝出螢幕。拖曳 n 放大範圍，並切換對數座標觀察「誰壓過誰」。

成長曲線 · 互動圖常見複雜度函數 vs. 輸入大小 n
1 (常數) log₂ n n n·log₂ n n² n³ 2ⁿ n!

「1」永遠躺平、log 慢速爬升、多項式加速成長、指數與階乘最後遙遙領先。 演算法設計的目標，就是把實際問題從中下方的曲線逼近到「可行」的範圍。

01.3 常見複雜度的等級

記號名稱典型例子n=10⁶ 的可行度
O(1)常數雜湊表取值、陣列索引瞬間
O(log n)對數二元搜尋、平衡樹約 20 步
O(n)線性線性搜尋、掃過一遍百萬步，輕鬆
O(n log n)線性對數Merge Sort、快速排序平均二千萬步，可接受
O(n²)平方氣泡排序、雙層迴圈10¹² 步，很慢
O(n³)立方樸素矩陣相乘、三層迴圈10¹⁸ 步，幾乎不可能
O(2ⁿ)指數窮舉所有子集合連 n=40 都跑不完
O(n!)階乘窮舉所有排列（旅行推銷員）n=20 已經天文數字

01.4 體驗：數一數操作次數

選一種寫法，看它在輸入 n 時實際執行了多少次內層操作。右側的倍數表則直接顯示——每當 n 加倍，各種複雜度的步數分別變成幾倍（2 倍、4 倍、8 倍、還是直接爆炸）。

操作次數 · 互動計數四種程式在輸入大小 n 時的內層操作次數
線性搜尋 n 次 氣泡排序 n(n−1)/2 次 矩陣相乘 n³ 次 費氏數列遞迴 ≈2ⁿ(個呼叫)

n 加倍時，步數成長幾倍？

nn（線性）n²/2（氣泡）n³（矩陣）2ⁿ（費氏）n!（排列）

留意最後三列：n 從 20 → 40 → 80 時，2ⁿ 與 n! 的數字立刻超過人類能「計時」的範圍——這就是指數爆炸 (exponential explosion)。

01.5 如何寫出遞迴關係

著名例子：費氏數列 F(n)=F(n−1)+F(n−2)。它的時間複雜度滿足遞迴關係

T(n) = T(n−1) + T(n−2) + 1      （每次呼叫多了 1 個常數＋兩個子呼叫）
解出：T(n) = Θ(2ⁿ)               （指數！太慢了）

同一問題改用「從底部填表」的動態規劃後，只要 O(n)（見第 07 章）。這就是複雜度分析最重要的用途：逼我們換方法。

判斷迴圈複雜度的小技巧
一層迴圈大致 n 次 → O(n)；兩層各自跑 n 次 → O(n²)；三層 → O(n³)； 每層只跑一半（n/2）仍是 O(n)；每次砍半（二分搜尋）才是 O(log n)。
