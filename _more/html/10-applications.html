10 領域應用 演算法在最常見的問題上，怎麼落地

前面九章是「方法工具箱」。這章挑一個最常用到的場景——在長字串裡找短字串 （搜尋引擎、文字編輯器、DNA 比對都用它）——看看「方法的改良」能省下多少力氣。

10.1 字串搜尋：暴力 vs KMP

暴力法在每個位置試著對齊模式，失敗就「左移一格」再來。最糟情況（例如大量相同字元）會退化成 O(nm)。

# 暴力：每次都把模式往右挪一格
for s in 0..n-m:
    for j in 0..m:                # 對齊比較
        if text[s+j]] != p[j]: break
        if j == m: 找到一處

# KMP：先算「跳過表」π，失敗時依據 π 一次跳過已確認相同的前綴
失敗時：j ← π[j-1]（text 指標不退回），可以保證 O(n+m)
```
KMP 的關鍵想法
當 pattern 的第 j 字元失配時，前面的 j 個字元已經比對成功過。 π[j−1] 告訴我們：這些字元裡「最長的真前綴 = 真後綴」有多長， 直接把 j 跳回那麼長——絕不把 text 指標往回走。

10.2 為什麼 O(n+m) 值得追求

假設 text 長 100 萬字元、pattern 長 1000：暴力最糟要吃 10⁹ 次比較；KMP 保證最多約 2×10⁶ 次。

方法時間例子
暴力O(n·m)（最糟）DNA「ACGT」重複序列時退化
KMPO(n+m)永遠線性，pattern 再長都不怕
Boyer-Moore / Rabin-Karp平均更快實際搜尋引擎、grep 常用
更多應用連結
同一套「預處理 + 跳過」的精神也出現在：影像的邊緣偵測（卷積）、 密碼學的雜湊（SHA）、編譯器的 BNF 剖析（遞迴下降）、以及電路的模擬（第 03 章領域）。 學了方法，剩下的就是「把它用到對的地方」。
