# 幾百億美金的打字錯誤：二元搜尋法 Bug

**領域**：[排序與搜尋](排序演算法.md) | **年代**：1946–2006 | **相關**：[Donald Knuth](排序演算法.md)

---

1946 年，約翰·莫奇利（John Mauchly）就提出了二元搜尋法的概念——就是猜數字遊戲裡每次都從中間切一半的策略。這個邏輯聽起來簡單到不行，對吧？

然而，全球的電腦科學家在接下來的 12 年裡，寫出的二元搜尋法**全都帶有 Bug**！甚至到了 1962 年，《紐約時報》報導著名電腦科學家高德納（Donald Knuth）發表了第一個「完全正確」的二元搜尋演算法。

結果到了 **2006 年**（過了整整 60 年），一位 Google 工程師在檢視 Java 標準庫時發現：裡面的二元搜尋法**依然有 Bug**——當陣列太長時，計算中間索引的 `(low + high) / 2` 會發生**整數溢位**（Integer Overflow），導致存取到錯誤的記憶體位置。

一個小小的加號，讓全世界頂尖工程師集體卡關了幾十年。

修正方法極其簡單：`low + (high - low) / 2`。但發現這個問題花了 60 年。

---

**教訓**：越是「顯而易見」的演算法，越容易隱藏邊界條件的陷阱。
